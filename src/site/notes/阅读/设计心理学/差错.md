#### 定义：差错，失误和错误

- 人为差错：任何违背‘合理“的行为 / 与普遍接受的正确或合理的行为有所偏离
- 差错分类：
	- 失误
		- 定义：当人们打算做一件事情，结果却做了另外一个事，就产生失误
		- 失误产生的后果：所执行的行动与预计的行动不一致
		- 分类：
			- 行动失误：执行了错误的动作
			- 记忆失效：丧失记忆，原本打算做的事情没有做，或者没有及时评估其行动结果
	- 错误
		- 定义：为达到不正确的目的或者形成错误的计划，就是错误
		- 即使执行了正确的行动，也是错误的一部分，因为行动本身就是不合理的
		- 分类
			- 违反规则：犯错的人恰如其分地分析了情况，但是决定采取不正确的行动，遵循错误的规则
			- 缺乏知识：由于不正确或者不完善的知识，问题被误判
			- 记忆失效：在目标、计划或者评价阶段有所遗漏
#### 差错和行动的七个阶段

- 错误：在设定目标或者计划的时候，也发生在比较行动结果和预期目标的时候
- 失误：执行计划的时候，或者发生在感知和解释结果的时候
- 记忆失效：可能发生在每个阶段之间的八个转换过程中

### 失误的分类

- 佛洛依德：某些事物具有隐含的，不为人知的意义，但是大多数失误都可以用简单的心理机制加以解释
- 失误的特点：和新手相比，越是熟练的人失误越多
- 一些失误是由于动作之间的相似性造成的
- 分类
	- 撷取性失误(capture slips)
		- 定义：指某个经常做的动作,或刚刚做过的动作突然取代了 想要做的动作,即某个曾经的动作挤占了需要完成的动作
		- 原理：两个动作之间的其中一部分动作序列是相同的，但你对其中一个行动序列远比另外一个更熟悉。相同部分完成之后，更频繁或者更接近的行动会继续进行，而预期的行动被搁置了
		- 特点：有经验和有技巧的人比初学者更容易犯撷取性失误
		- 避免：设计师要避免有相同其实步骤，然后发散的流程。只要可能，应该从一开始就**设计出不同的动作序列**
	- 描述相似性失误(description-similarity slips) 
		- 定义：差错发生在与目标相似的对象上，如果对目标的描述相当的含糊不清，就会发生描述相似性失误
		- 特点：具有的相同特征越多,就越有可能发生更多的失误；在同一时间出现更多相似的对象,描述相似性失误就越多
		- 避免：设计不同目的的控制和显示设备时，设计师需要确认它们之间有明显差异
	- 记忆失效性失误
		- 原因：记忆中断（动作开始与动作完成之间介入了意外事件）
		- 我们所使用的机器设备会经常有介入，在开始和完成之间存在许多步骤，使得短期记忆 / 工作记忆的能力超过负荷
		- 避免
			- 使用最少得步骤
			- 对需要完成的步骤提供生动有效的提醒
			- 强制功能
			- 但是不是所有的记忆失效错误都可以找到简单的解决方案
	- 功能状态失误
		- 定义：设备有不同的状态，而相同的控件具有不同的含义，就可能发生功能状态失误
		- 如果设备可能的操作模式比它的控制组件还多，功能状态失误就不可避免
		- 模式失误是真正的设计错误，当设备不能显示可见模式的时候，尤其容易发生模式失误
			- 设计师必须使设备能够明显地显示所激活的功能模式
			- 或者经常设计出可以抵消干扰活动对已经设定的模式带来影响的系统
### 错误的分类

- **基于规则的错误**
	-  发生方式
		- 错误地理解了问题
		- 采用了正确的规则，但是规则本身就有问题
		- 采用了正确的规则，但是不正确地评估行为的结果
	- 基于规则的错误很难避免，也很难检测
		- 在复杂的情况下，太多信息就是问题所在
		- 迫于时间压力做出决策，很难知道哪些证据已经被考虑，哪些被摒弃
		- 在处理常规事件时得心应手的能力，会让我们在碰到异常事件时犯下严重的错误
	- 设计师应该怎么做？
		- 提供尽可能多的指导，确保现状以一个连贯的核容易理解的形式呈现出来——最好是图像化
		- 当事件发生的时候，人们很可能被太多无关信息淹没，而不是置身于很多有用信息之中，他们怎么知道哪些应该被优先处理，哪些应该被忽略？
		- 设计的挑战是将当前系统状态的信息，以便于理解和阐释的方法呈现出来，以及提供必要的说明和解释。
		- 如果每个行为都需要密切关注，则无人能做到
- 基于知识的错误
	- 以知识为基础的行为发生时，人们在有意识地区解决问题
	- 最好的办法是深入了解情况，在大多数情况下人们可以借助适当的概念模型来解决问题
	- 在复杂的情况下，人们可能需要帮助，这需要良好的合作解决问题的技能和工具（程序手册，智能计算机系统)
- 记忆失效的错误
	- 中断导致人们忘记正在对目前环境状态所做的评判
	- 设计师
		- 确保所有相关的信息连续可用
		- 减少中间繁琐的设计
		- 假设人们可能被打断，在回复操作时帮助他们
### 社会和习俗压力

- 在工业领域，社会压力会导致误解、错误和事故
-  在商业环境中，维护系统运行的压力是巨大的，如果一个昂贵的系统停机了，就会损失相当多的钱，运营商往往在压力下不会让系统停摆，有时结果就是悲剧
>[!example1]
>1977年,在加那利群岛的特内里费,荷兰皇家航空公司的一架波  音747客机在起⻜时与正在跑道上滑行的一架泛美747客机相撞,导致  583人遇难。
>荷航的⻜机当时不应该起⻜,但因天气开始变坏,况且这 一航班已经延误多时(起初正是由于天气恶劣,这架客机无法⻜往原  定目的地,才改道降落在加那利群岛),⻜行员未经许可,便决定起  ⻜。
>泛美客机当时也不应该在跑道上滑行,之所以如此,是因为⻜行  员和⻜行调度中心之间产生了很多误解。
>造成空难的另一个原因是,  当时的雾气很浓,两架客机的驾驶员彼此都看不清对方”

>[!example2]
>在学校考试中作弊，或帮助他人作弊，或不报告其他作弊者

>[!example3]
>当一些潜水员陷入了麻烦,需要快速上升到水面,或当他们已经  在水面,想靠近海岸但是被波浪颠来倒去,还有一些因为他们被自己  的配重所拖累,就有可能被淹死。由于配重很昂贵,他们不想轻易释 放。此外,如果潜水员释放掉配重,然后安全返回,他们就无法证明  释放配重是必要的,所以会觉得不好意思,**形成自我诱导的社会压力**。
>我们的教练非常清楚,当学员不能完全肯定释放配重是必要的时  候,在采取此关键步骤时所产生的负面心理。为了**消解这种心理**,他  宣布,如果有人为安全起⻅扔掉配重,他会公开表扬并且无偿提供新  的配重。这是克服社会压力的一个非常有说服力的尝试。

- 社会压力不断出现，但是很难被记录下来
	- 大多数人和组织都不愿意承认这些因素，即使在事故调查中发现有社会压力的因素，其结果也往往隐匿不见，得不到公众的仔细监督
- 如何克服此类问题？
	- 仅有好的设计还不够，我们需要不同的培训
	- 奖励安全，将其置于经济压力之上
	- 设备可以使潜在的危险可见和明确
	- 对公司的政策进行改善

- 检查清单
	- 好处：可以增加行为的准确性和减少差错，特别是失误和记忆失效
	- 两个人一起作为一个团队使用检查单，效果会更好
		- 相反：如果一个人先执行，后一个人稍后检查，效果就不是很理想
			- **群体的追随模式**：如果增加更多的人来检查任务，并不能保证把事情做对
	- **推行困难**
		- 它使人觉得自己的能力受到怀疑
		- 资历较浅的人需要检查资料较深的人的工作，在许多文化中这强烈地违背了权利的等级分配
		- 其实犯错是人的本性：精神紧张，或者在时间压力 / 社会压力下 / 在多次打断之后，我们都会有失误和错误，每样检查都必不可少
	- 电子清单的优点
		- 它们可以跟踪被跳过的项目，如果有未完成的项目，清单将不会被标志为完成状态，直到所有的项目已经被完成
		- 除非是任务需要，**将顺序结构强加于任务实施，是一个糟糕的设计**
